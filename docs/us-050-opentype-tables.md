# US-050: lecture des tables OpenType de base

`atelier-font` lit des conteneurs sfnt TrueType (`0x00010000`, `true`, `typ1`), OpenType/CFF (`OTTO`) et collections TTC (`ttcf`). `FontFace::parse` sélectionne la face zéro. `FontFace::parse_collection(bytes, index)` permet de choisir une face TTC ; un index invalide renvoie `FaceIndexOutOfRange`.

Le parseur exige `head`, `hhea`, `hmtx`, `maxp`, `name`, `OS/2`, `post` et `cmap`. Les données brutes de chaque table restent empruntées au buffer source et sont accessibles par `table([u8; 4])`. `metrics()` donne les champs de `head`, `hhea`, `maxp`, `OS/2` et `post`; `names()` retourne les enregistrements décodés. Les unités UTF-16 invalides sont remplacées par U+FFFD ; une longueur UTF-16 impaire est refusée. Les autres encodages de noms sont exposés en conversion octet vers caractère.

`glyph_index(char)` retourne le glyphe zéro pour un caractère absent. Le premier format disponible est sélectionné dans l'ordre 12, 4, 6 et utilisé seul. Pour chaque format, la préférence déterministe est Windows UCS-4 (plateforme 3, encodage 10), Unicode (plateforme 0), Windows Unicode BMP (plateforme 3, encodage 1), puis Windows Symbol (plateforme 3, encodage 0). `variation_glyph(base, selector)` renvoie `NonDefault(gid)` pour une entrée explicite, `Default` si la plage de défaut demande d'utiliser le cmap de base, et `Unsupported` si aucune entrée utilisable n'existe. `horizontal_metric(gid)` retourne l'avance et le LSB ; après `numberOfHMetrics`, l'avance de la dernière métrique longue est réutilisée.

Le parsing vérifie les signatures et versions prises en charge, les plages des tables requises et des sous-tables cmap prises en charge (formats 4, 6, 12 et 14), les additions/multiplications d'offsets, les tailles minimales, les comptes et les références de glyphes. Les autres formats cmap ne sont pas interprétés. Limites défensives : 256 Mio par fichier, 4 096 faces, 4 096 tables, 1 024 enregistrements cmap, 16 384 noms, 4 Mio cumulés d’octets de noms encodés référencés (texte décodé borné proportionnellement) et 1 000 000 unités de travail de validation cmap. Les offsets TTC sont relatifs au fichier ; ceux des sous-tables cmap sont relatifs à la table cmap. Les tables de contours, le shaping, GPOS et GSUB ne sont pas interprétés.

`FontError` distingue les fonctions non prises en charge, signature/version invalides, troncature, plages invalides, données incohérentes, limites et table requise absente. Aucune erreur de données n'entraîne une panique ; les tables ne sont pas copiées lors du parsing. Les noms Windows plateforme 3 encodages 3, 4 et 5, ainsi que les plateformes non Unicode, sont convertis octet par octet en points de code Latin-1, sans interprétation propre à leur page de codes. Les autres noms Unicode sont décodés depuis UTF-16BE ; les unités mal formées donnent U+FFFD.

Les preuves de validation et les limites d’intégration sont rassemblées dans le [suivi du lot](MODEL-FONT-PROGRESS.md).
