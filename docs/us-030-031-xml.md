# XML en flux : US-030 et US-031

**État : US développées, revues et validées le 2026-10-10.** Le lecteur borne les allocations cumulées des namespaces actifs et ignore le contenu DTD avec un scanner sans croissance liée aux déclarations.

`atelier-xml` expose un lecteur événementiel qui prend un `std::io::Read` et un écrivain qui prend un `std::io::Write`. Le module n'a aucune dépendance externe et interdit `unsafe`. Il ne construit pas de DOM : `Reader::next_event` lit seulement jusqu'au prochain événement. Les chaînes courantes sont bornées par `Limits`; le flux entier n'est jamais gardé en mémoire.

## Lecture

```rust
use atelier_xml::{Event, Reader};
use std::{fs::File, io::BufReader};

let input = BufReader::new(File::open("document.xml")?);
let mut reader = Reader::new(input);
while let Some(event) = reader.next_event()? {
    match event {
        Event::StartElement { name, attributes, .. } => {
            println!("élément {} dans {:?}", name.local, name.namespace);
            for attribute in attributes {
                println!("{} = {}", attribute.name.local, attribute.value);
            }
        }
        Event::Text(text) => consume_text(&text),
        Event::EndElement { name } => close_element(&name),
        Event::Comment(_) | Event::ProcessingInstruction { .. } => {}
    }
}
# Ok::<(), Box<dyn std::error::Error>>(())
```

`Name` garde le préfixe lexical, le nom local et l'URI résolue. Utilisez `Name::expanded()` pour comparer le couple `(URI, local)`. Le namespace par défaut s'applique aux éléments, jamais aux attributs sans préfixe. Les déclarations suivent les scopes et le parseur détecte les doublons d'attributs après résolution.

Le décodeur reconnaît UTF-8 (avec ou sans BOM) et UTF-16 LE/BE avec BOM. Il conserve les fragments d'encodage entre les lectures, rejette les séquences invalides sans U+FFFD et fournit ligne, colonne et offset dans `XmlError`. Les fins de ligne XML sont normalisées en LF; les espaces littéraux d'attribut sont normalisés, tandis que les références numériques conservent le caractère référencé. Seules les cinq entités prédéfinies et les références numériques sont décodées. Commentaires et instructions de traitement produisent des événements; CDATA produit `Text` équivalent. Un DOCTYPE est ignoré sans interpréter sa déclaration ni résoudre de ressource externe; les entités déclarées restent inconnues.

`Reader::with_limits(input, limits)` personnalise la profondeur, le nombre d'attributs, les tailles de noms/valeurs/texte, le nombre d'événements, les déclarations de namespace et le budget mémoire cumulé des bindings, piles, diagnostics et événement courant. Les plafonds sont vérifiés avant l'extension des chaînes gouvernées. Les défauts sont 256 niveaux, 256 attributs, 1 024 octets par nom, 1 Mio par valeur d’attribut, 4 Mio par texte, 10 millions d’événements, 256 déclarations namespace par élément et 16 Mio de mémoire cumulée. Les événements que l’appelant conserve ne font plus partie des buffers du lecteur. Le nombre d’événements est contrôlé avant parsing du prochain événement; au budget exact, la fin blanche puis EOF restent acceptées.

`Reader::new` est strict : toute erreur d'encodage, caractère XML interdit, référence inconnue ou syntaxe malformée arrête la lecture. `Reader::new_tolerant` est opt-in et répare uniquement une fermeture finale manquante en émettant les fins d'élément correspondantes; `diagnostics()` conserve l'emplacement et le détail de cette réparation. Il ne répare jamais les octets invalides, les caractères interdits, les namespaces invalides ni les limites dépassées.

## Écriture

```rust
use atelier_xml::{Event, Name, Writer};

let mut writer = Writer::new(Vec::new())?;
let root = Name { prefix: None, local: "document".into(), namespace: Some("urn:example".into()) };
writer.write_event(&Event::StartElement { name: root.clone(), attributes: vec![], empty: false })?;
writer.write_event(&Event::Text("A & B".into()))?;
writer.write_event(&Event::EndElement { name: root })?;
let bytes = writer.finish()?;
# Ok::<(), Box<dyn std::error::Error>>(())
```

Le writer écrit une déclaration UTF-8, échappe les valeurs, vérifie les noms/caractères et équilibre les éléments. Il génère des préfixes `ns0`, `ns1`, … à partir de l'ordre de première apparition des URI; la sortie est donc reproductible pour les mêmes événements. Les CR et CRLF fournis dans `Text` ou les valeurs d'attribut sont écrits comme `&#13;`; les CR/CRLF dans un commentaire ou une instruction de traitement sont normalisés en LF, car XML ne permet pas de référence de caractère dans ces constructions. Cela correspond à la normalisation des fins de ligne faite par le lecteur. Il n'invente pas de fermeture à `finish()` et retourne `WriterState` si la pile n'est pas vide ou si une fermeture ne correspond pas. Une erreur d'I/O est propagée comme `ErrorKind::Io`.

Les fixtures de référence se trouvent dans `tests/format-reference/xml/`; elles couvrent les frontières UTF, namespaces, syntaxe courante, erreurs strictes et absence d'expansion DTD.
