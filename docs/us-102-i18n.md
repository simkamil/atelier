Livrables : `web/i18n.mjs` (catalogue, paramètres, pluriels, formatage fr-FR), `tests/check-i18n.mjs` (contrôle), `tests/i18n-baseline.txt` (écarts connus), `tests/i18n.mjs` (51 tests). Aucun écran existant n’est modifié : le branchement revient à l’intégrateur. Le fichier `web/i18n/fr-FR.txt` n’a reçu que 5 clés d’exemple en fin de fichier (bloc commenté).

## Format du catalogue

Une entrée par ligne, `clé=valeur`. La première `=` sépare clé et valeur ; les lignes vides et celles qui commencent par `#` sont ignorées. Clé : lettres, chiffres, `.`, `_`, `-`, sans espace. Le format des 80 clés existantes est inchangé (un test compare `parseCatalog` à l’ancien `loadCatalog` sur le vrai fichier).

`parseCatalog(texte)` rapporte au lieu d’ignorer : `invalid-line` (pas de `=`), `invalid-key`, `duplicate-key` (la dernière occurrence l’emporte, comme avant) et `invalid-message` (syntaxe du message).

| Écriture | Sens |
|---|---|
| `{nom}` | paramètre nommé |
| `{n, plural, one {# page} other {# pages}}` | pluriel (sous-ensemble d’ICU MessageFormat) |
| `#` dans une branche de pluriel | le nombre, formaté par la locale |
| `\n` `\\` `\{` `\}` `\#` | saut de ligne, barre oblique inverse, accolades et dièse littéraux |

Toute autre séquence `\x` est une erreur de syntaxe. Sélecteurs de pluriel : `zero one two few many other` et les valeurs exactes `=0`, `=1`… ; `other` est obligatoire ; une branche `many` absente retombe sur `other`.

**Choix du pluriel ICU plutôt que des clés suffixées (`cle.one`).** La phrase reste entière dans une seule entrée (le traducteur la voit d’un bloc), plusieurs pluriels peuvent cohabiter dans un message, `#` évite de répéter le nombre, et l’outil valide la syntaxe et les paramètres de façon statique sans multiplier les clés « inutilisées ».

## API (`web/i18n.mjs`)

`createI18n({ locale = "fr-FR", catalog, dev = false, onIssue })` renvoie un objet figé :

- `t(clé, paramètres)` : texte brut. **L’appelant doit l’affecter par `textContent` ou `setAttribute`, jamais `innerHTML`** : les valeurs sont insérées telles quelles, jamais réinterprétées (balisage, accolades, `\n`, `#`). Les nombres sont formatés par la locale, les chaînes insérées verbatim.
- Paramètre manquant (absent, `null`, `undefined`, ou hérité du prototype) : **développement** (`dev: true`) → `I18nError` de code `missing-param` ; **production** → le repère `{nom}` reste visible dans le texte et l’incident est signalé. Choix : un texte incomplet mais lisible vaut mieux qu’une interface cassée, et le repère se repère à l’œil et à la recherche.
- Clé absente ou message invalide : jamais d’exception ; rendu `⟦clé⟧` et signalement (`console.warn` en développement, ou `onIssue`, dédoublonné ; `issues` garde les 200 premiers).
- `has(clé)`, `locale`, `pluralCategory(n)`.
- `catalog` : texte du fichier, résultat de `parseCatalog`, `Map` ou objet.
- Formatage : `formatNumber(n, {decimals, maxDecimals, grouping})`, `formatPercent(fraction, …)`, `formatDate(d, {style: "long"|"short", timeZone})`, `formatTime`, `formatDateTime`, `formatLength(valeur, {from: "pt"|"twip"|"in"|"cm"|"mm", to: "pt"|"in"|"cm"|"mm", decimals, maxDecimals})`, `formatFileSize(octets, {binary})`, `formatList(items, {type: "and"|"or"})`, `convertLength`. Une date invalide, une unité inconnue ou une taille négative lèvent `I18nError` (erreur de programmation).
- Exports : `parseCatalog`, `compileMessage`, `analyzeMessage`, `pluralCategory`, `pluralSelector`, `verifyPluralRules`, `registerLocale`, `getLocaleData`, `I18nError`.

Résultats figés par les tests (U+202F = espace fine insécable) : `1 234 567,891` ; `25,6 %` ; `2,54 cm` (72 pt) ; `210 mm` (11 906 twips) ; `1 po` ; `13 octobre 2026`, `13/10/2026`, `14:30`, `13 octobre 2026 à 14:30` ; `1er octobre 2026` ; `512 octets`, `1,5 Ko`, `1 Mo` (999 999 octets) ; `a, b et c`. Arrondis par défaut : mm 1, cm 2, pt 1, po 2 décimales au plus. Les tailles sont décimales par défaut (Ko, Mo, Go) ; `binary: true` donne Kio, Mio, Gio (le catalogue actuel écrit « 128 Kio » pour la limite de fichier).

### Pluriels français

Règles CLDR : `one` pour la partie entière 0 ou 1 (donc 0, 0,5, 1, 1,5, 1,99) ; `many` pour les multiples exacts d’un million ; `other` sinon ; le signe est ignoré. `Intl.PluralRules("fr-FR")` est utilisé s’il concorde avec la table de référence du module sur des valeurs sondes (`verifyPluralRules`) ; sinon (ICU ancien sans `many`) la table de référence prend le relais. Au-delà de 2^53 les entiers ne sont pas garantis.

### Variations d’`Intl` normalisées

Constatées ou possibles selon la version d’ICU : séparateur de milliers (U+202F ou U+00A0), espace avant `%` (U+00A0 observé avec ICU 78, U+202F ailleurs), espace nombre-unité (U+202F ou U+00A0), « 1 octobre » ou « 1er octobre », `-0`, heure « 24:05 » avec `hour12:false`. Le module assemble le résultat à partir de `formatToParts` : séparateurs, espace nombre-unité/pourcent (toujours U+202F), « 1er », « à » entre date et heure, `-0` → `0`, horloge `h23` viennent des données de locale, pas d’ICU. Aucune U+00A0 ne sort du module (testé). Restent dépendants d’ICU : noms des mois et libellés de `Intl.ListFormat`, figés par les tests.

### Ajouter une locale

`registerLocale("de-DE", { group, decimal, unitSpace, dateTimeJoiner, firstDaySuffix, lengthUnits, byte, byteUnits, pluralCategories, plural })` (voir l’entrée `fr-FR`), puis un fichier `web/i18n/de-DE.txt`. Sans données enregistrées, `createI18n` retombe sur `Intl` seul. L’outil compare les clés de chaque autre catalogue à celles de `fr-FR` (`locale-missing`, `locale-extra`).

## Outil `tests/check-i18n.mjs`

```text
node tests/check-i18n.mjs                  compare à tests/i18n-baseline.txt ; code 1 si un écart est nouveau
node tests/check-i18n.mjs --strict         ignore la référence ; tout écart échoue
node tests/check-i18n.mjs --update-baseline  réécrit la référence (après correction, jamais pour masquer)
options : --root=<dossier>  --baseline=<fichier>  --quiet (résumé des écarts connus)
```

Sortie `fichier:ligne: [catégorie] message` ; code 0 (aucun nouvel écart), 1 (écarts), 2 (argument inconnu). Il lit `web/**/*.mjs|js`, `web/index.html` (y compris les scripts en ligne) et `web/i18n/*.txt`, avec un vrai analyseur de jetons (`tokenize`) qui distingue commentaires, chaînes, gabarits imbriqués et expressions régulières.

Catégories : `missing-key`, `unused-key`, `hardcoded`, `param-missing`, `param-extra`, `message-syntax`, `plural-category` (branche que le français ne sélectionne jamais), `duplicate-key`, `invalid-line`, `invalid-key`, `locale-missing`, `locale-extra`, `invalid-exemption`, `no-catalog`.

**Clés utilisées** : `t("…")`, `i18n.t`, `messages.get(…)`, `catalog.get`, `FALLBACK.get` (littéraux du premier argument, y compris les deux branches d’un ternaire ; `theme-${x}` marque le préfixe `theme-` comme utilisé), `data-i18n`, `data-i18n-*`, sélecteurs `[data-i18n="…"]`, et tout littéral égal à une clé existante hors position de clé d’objet (utilisation indirecte, par exemple `command("new", "action-new", …)`). Une clé calculée (`messages.get(result.key)`) n’est pas vérifiable.

**Paramètres** : pour `t("clé", { … })` avec un littéral d’objet sans spread ni clé calculée, les propriétés sont comparées aux `{nom}` et variables de pluriel du message. Indécidable (variable, spread) : ignoré.

**Chaînes en dur** : littéral ou gabarit (texte statique seulement) comptant une lettre accentuée ou deux mots, ou, dans un emplacement d’affichage certain (`textContent`, `innerText`, `title`, `placeholder`, `alt`, `ariaLabel`, `setAttribute` sur `aria-label`/`title`/`placeholder`/`alt`…, propriétés d’objet `label`/`title`/`text`…, `append`), un mot de 3 lettres. En HTML : nœuds de texte et attributs `aria-label`, `title`, `placeholder`, `alt`. Ne sont pas signalés : commentaires, expressions régulières, sélecteurs CSS, URL et chemins, listes de classes (`ui-button ui-toggle`), identifiants composés, clés d’objet, `case`, comparaisons, importations, arguments d’API DOM et d’événements (`addEventListener`, `querySelector`, `classList`…), `new XxxError(...)`, `console.*`, `assert*`, `fail*`, `invalid*`, `reject*`, expressions glissées dans un gabarit (`${w}px ${h}px`), éléments portant `data-i18n` (leur texte est le repli) et attributs doublés de `data-i18n-<attribut>`.

**Exemptions** (toujours avec une raison ; sans raison, `invalid-exemption`) :
- `// i18n-ignore: raison` ou `/* i18n-ignore: raison */` sur la ligne, ou seul sur la ligne précédente ; `<!-- i18n-ignore: raison -->` en HTML ;
- `ALLOWED_TEXT` dans le script (« Atelier », nom du produit) ;
- `DIAGNOSTIC_MODULES` : modules du moteur et des protocoles (`wasm-loader`, `wasm-protocol`, `editor-protocol`, `display-list`, `engine-client`, `engine-worker`, `i18n`) dont les chaînes **sans lettre accentuée** sont des diagnostics de développeur en anglais ; une chaîne accentuée y reste signalée.

Limites : pas d’évaluation de code ; un texte d’interface en anglais sans accent d’un seul mot hors emplacement d’affichage certain n’est pas vu ; les phrases en anglais construites dans un module non listé sont signalées (à exempter avec raison).

### Fichier de référence

`tests/i18n-baseline.txt` : `nombre<TAB>catégorie<TAB>fichier<TAB>détail`, sans numéro de ligne (un décalage de lignes ne casse pas la comparaison ; les doublons sont comptés). Un écart absent de la référence (ou au-delà de son compte) fait échouer ; les écarts connus sont listés ; ceux de la référence qui ont disparu sont signalés pour qu’on régénère le fichier.
